HTML-парсинг: порядок дій під час пісомки

Ця інструкція не потребує жодного прикладового файла поруч. Код нижче використовує структуру з твого cvicenie6/source/kino-hviezda.html; потрібний фрагмент HTML наведений у кроці 2. Коли на пісомці дадуть інший файл, змінюй селектори відповідно до нього. Усі готові блоки дій — у Sources.

Маршрут: адреса джерела → структура → селектори → текст → об’єкти → перевірка → показ → інтерактивність.

1. Визнач, де саме лежать дані 2. Спочатку знайди повторювану структуру 3. Перевір селектори, перш ніж писати парсер 4. Якщо потрібен fetch, читай HTML як текст 5. Перетвори текст на окремий DOM-документ 6. Нормалізуй текст 7. Число з ціни: кома, знак € і відсутнє значення 8. Читай поля всередині ОДНОГО запису 9. Склади дані в об’єкти, а не в HTML-рядки 10. Перевір об’єкти до створення CSS та фільтрів 11. Покажи дані безпечно 12. Лише потім додавай фільтри, кнопки й CSS 13. Якщо отримав порожню сторінку: порядок діагностики 14. Остання перевірка перед здачею

1. Визнач, де саме лежать дані

Дія: Відкрий наданий HTML і знайди, чи дані вже всередині поточної сторінки, чи умова дає окрему адресу HTML.

Якщо дані є у відкритому DOM, читай document. Якщо потрібно завантажити HTML як у Z2, роби fetch за реальною браузерною адресою. /public_html у FileZilla — каталог на сервері, не частина URL для fetch.

// ВАРІАНТ А: дані є у відкритому HTML
const doc = document;

// ВАРІАНТ Б: треба завантажити цей самий HTML через fetch
const sourceUrl = location.pathname;

// ВАРІАНТ В: окремий HTML — візьми ТОЧНУ адресу з умови,
// а не вигадану назву файлу.

Контроль: У Network адреса запиту має відкритися зі статусом 200. При file:// запусти локальний/шкільний сервер.

2. Спочатку знайди повторювану структуру

Дія: Відкрий HTML-код. Познач зовнішній блок одного дня або картки, потім поля всередині нього.

У твоєму cvicenie6/source/kino-hviezda.html повторюється section.den, усередині нього li.film. Це реальний зразок із твоїх матеріалів. На пісомці класи можуть називатися інакше, тому не копіюй їх без перевірки.

<section class="den">
  <h2>Pondelok <small>2. 11.</small></h2>
  <ul class="filmy">
  <li class="film">
    <span class="cas">17:30</span>
    <a class="nazov">Robot Ferko zachraňuje svet</a>
    <span class="cena">5,90 €</span>
  </li>
  </ul>
</section>

Контроль: Запиши на папері або в коментарі: група .den; запис .film; поля .cas, .nazov, .cena.

3. Перевір селектори, перш ніж писати парсер

Дія: У Console перевір кількість знайдених блоків. Підстав класи з наданого HTML.

querySelector знаходить перший елемент або null. querySelectorAll дає всі збіги. Якщо результат 0, наступний код не допоможе, поки не виправиш селектор.

console.log(document.querySelectorAll(".den").length);
console.log(document.querySelector(".den")?.querySelectorAll(".film").length);

Контроль: Для знайомого файлу cvicenie6 результат має бути більше нуля; для іншого файлу орієнтуйся на його реальну структуру.

4. Якщо потрібен fetch, читай HTML як текст

Дія: В async-функції завантаж точний URL і перевір response.ok.

fetch не кидає виняток при HTTP 404. response.text() дає рядок, з яким ще не можна працювати як із DOM.

async function loadHtml(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return await response.text();
}
// Для того самого HTML: const html = await loadHtml(location.pathname);

Контроль: Постав console.log(html.slice(0, 100)): має починатися HTML, а не повідомленням про помилку.

5. Перетвори текст на окремий DOM-документ

Дія: Після await loadHtml(...) виклич DOMParser.

Тепер doc підтримує querySelector/querySelectorAll. Якщо дані вже в поточній сторінці й fetch не потрібен, doc = document — цей крок пропускаєш.

const html = await loadHtml(location.pathname);
const doc = new DOMParser().parseFromString(html, "text/html");
console.log(doc.querySelectorAll(".den").length);

Контроль: Кількість знайдених груп має бути такою самою, як при огляді вихідного HTML.

6. Нормалізуй текст

Дія: Оголоси cleanText один раз перед функцією парсингу.

У HTML між словами бувають переноси, табуляція і нерозривні пробіли. textContent бере їх усі. Ця функція приводить текст до одного пробілу між словами.

function cleanText(value) {
  return String(value ?? "").replace(/\u00a0/g, " ").replace(/\s+/g, " ").trim();
}

Контроль: cleanText(" Robot Ferko zachraňuje svet ") має дати "Robot Ferko zachraňuje svet".

7. Число з ціни: кома, знак € і відсутнє значення

Дія: Оголоси parsePrice поруч із cleanText.

Зберігай ціну як число, щоб її можна було сортувати та підсумовувати. Якщо її не вказано, поверни null; це не те саме, що 0.

function parsePrice(value) {
  const text = cleanText(value).replace(",", ".");
  const match = text.match(/\d+(?:\.\d+)?/);
  return match ? Number(match[0]) : null;
}
// "5,90 €" → 5.9; "Cena neuvedená" → null

Контроль: Number("5,90 €") дає NaN; parsePrice("5,90 €") дає 5.9.

8. Читай поля всередині ОДНОГО запису

Дія: У циклі по .film викликай film.querySelector, не doc.querySelector.

Інакше кожний запис може отримати назву або ціну першого фільму в документі. ?. дозволяє обробити відсутню ціну.

function textOf(parent, selector) {
  return cleanText(parent.querySelector(selector)?.textContent);
}
for (const film of section.querySelectorAll(".film")) {
  const time = textOf(film, ".cas");
  const title = textOf(film, ".nazov");
  const price = parsePrice(textOf(film, ".cena"));
  console.log({ time, title, price });
}

Контроль: На кожному рядку в Console повинні бути різні назви й часи.

9. Склади дані в об’єкти, а не в HTML-рядки

Дія: У функції parseProgram(doc) обійди групи, потім записи кожної групи.

Такі об’єкти легко фільтрувати й перевіряти. Пропускай запис без обов’язкових полів. День із нулем записів може бути коректним — у cvicenie6 є закритий день.

function parseProgram(doc) {
  const days = [];
  for (const section of doc.querySelectorAll(".den")) {
    const h2 = section.querySelector("h2");
    const day = cleanText(h2?.firstChild?.textContent);
    const date = textOf(section, "h2 small");
    const films = [];
    for (const film of section.querySelectorAll(".film")) {
      const time = textOf(film, ".cas");
      const title = textOf(film, ".nazov");
      if (!time || !title) continue;
      films.push({ time, title, price: parsePrice(textOf(film, ".cena")) });
    }
    days.push({ day, date, films });
  }
  if (!days.length) throw new Error("Не знайдено жодної групи: перевір селектор");
  return days;
}

Контроль: Після виклику має бути масив днів; усередині кожного — масив films.

10. Перевір об’єкти до створення CSS та фільтрів

Дія: Виклич парсер і виведи плоску таблицю в Console.

Так одразу видно порожню назву, некоректну ціну або неправильне групування. Коли дані неправильні, спершу виправ селектори й очищення.

const days = parseProgram(doc);
console.table(days.flatMap(d => d.films.map(f => ({ day: d.day, ...f }))));
console.log("Днів:", days.length);
console.log("Фільмів:", days.reduce((n, d) => n + d.films.length, 0));

11. Покажи дані безпечно

Дія: У render(days) створи елементи для видимої сторінки.

textContent показує витягнутий текст як текст. Не вставляй чужий HTML через innerHTML. Якщо в завданні вже є #results, використовуй його; інакше створи контейнер.

const results = document.querySelector("#results") ?? document.body.appendChild(document.createElement("div"));
results.id = "results";
results.replaceChildren();
for (const day of days) {
  const heading = document.createElement("h2");
  heading.textContent = `${day.day} ${day.date}`;
  results.append(heading);
  for (const film of day.films) {
    const p = document.createElement("p");
    p.textContent = `${film.time} — ${film.title} — ${film.price ?? "cena neuvedená"}`;
    results.append(p);
  }
}

Контроль: Після повторного виклику не повинно з’явитися дубльованих записів: replaceChildren очищує попередній результат.

12. Лише потім додавай фільтри, кнопки й CSS

Дія: Відкрий Sources через посилання вгорі: окремі рецепти для фільтра дня, пошуку, підтвердження, модального вікна, сортування та адаптивного Grid.

Зберігай початкові об’єкти у стані; при зміні фільтра обчисли видимі записи й перемалюй їх. Не видаляй дані з оригінального масиву.

13. Якщо отримав порожню сторінку: порядок діагностики

Дія: Перевір Console і Network саме в такому порядку.

1) Чи завантажився script.js? 2) Чи отримав fetch HTTP 200? 3) Чи doc містить очікуваний блок? 4) Скільки груп і записів повертають селектори? 5) Чи правильний масив об’єктів? 6) Чи render отримав цей масив? Не виправляй CSS, якщо даних немає.

console.log("JS запустився");
console.log("Груп:", doc.querySelectorAll(".den").length);
console.log("Записів:", doc.querySelectorAll(".film").length);
console.table(days);

14. Остання перевірка перед здачею

Дія: Перевір широку й вузьку ширину, усі кнопки, порожній стан, відсутню ціну та Console без несподіваних помилок.

У коді немає Vue, React, Bootstrap, jQuery або CDN. Усі шляхи до файлів походять із наданого завдання чи з location.pathname, а не з вигаданого прикладу. Якщо парсиш HTML із іншою структурою, селектори змінені відповідно до нього.
